# Apple Silicon macOS 应用打包计划

> 按顺序执行，每项保留实际验证结果。

**目标** 交付包含初始 Core 的 Apple Silicon `Orca Tauri.app`，支持从空白数据目录启动。

**实现** 使用官方签名的 Orca 1.4.265 app 提取 darwin-arm64 原生槽和同版 Web 客户端，以锁定版本的 Node 构建 Core ZIP。Tauri 将 ZIP 与版本和摘要一起放入应用资源目录。只有用户尚未安装 Core 时，应用才通过现有离线安装流程验证并激活初始版本。

**参考** [macOS 优先顺序](../../../README.md) 和 [已完成的 macOS Core 验证](../../validation.md)。

## 1. 构建 Core ZIP

- [x] 固定官方应用版本、签名标识、commit、模板摘要和 arm64 Node 摘要。
- [x] 实现 macOS Core 提取，校验资源路径和模板条目，恢复已知原生可执行文件的权限。
- [x] 通过原生模块和 PTY 冒烟，生成 Core ZIP 和摘要清单。
- [x] 使用现有 `install_core` 入口在隔离数据目录安装 ZIP，验证 Core 真实启动和退出。输入来源校验、ZIP 数据和运行时回报要一致。

## 2. 打包 Tauri 应用

- [x] 从原生应用资源读取初始 Core，利用现有摘要校验、安装目录和激活指针。候选无法配对或激活时回收候选进程。
- [x] 加入 macOS 一键构建命令，使用锁定的 Tauri CLI 输出 arm64 `.app`。
- [x] 验证应用资源目录、plist、二进制架构和代码签名。

## 3. 验证应用交付

- [x] 从空白隔离配置启动打包后的应用，核对 Core 就绪、HTTP 入口、活动版本与关闭后的进程回收。
- [x] 在 macOS 的实际 Tauri 窗口验证 Web 客户端可以打开并完成配对。
- [x] 更新 README 的复现命令，记录实测范围。签名与启动情况由实际构建验证结果决定。
